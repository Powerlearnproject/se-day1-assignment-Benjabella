#Part 1: Introduction to Software Engineering

Explain what software engineering is and discuss its importance in the technology industry.
Software engineering is the process of using structured methods and tools to create, test, and maintain software systems that work well and meet user needs. Software engineering is important because it powers almost everything we use, from smartphones and social media to banking apps and self-driving cars. It drives innovation, improves efficiency in businesses, connects people globally, and ensures that software is reliable and safe to use.

Identify and describe at least three key milestones in the evolution of software engineering.
  1. The development of programming languages (e.g., Fortran, C) - Early programming languages like Fortran (1957) and C (1972) laid the foundation for writing efficient and structured code, enabling the creation of complex software systems.
  2. Establishment of Software Engineering as a Discipline (1960s) - The term "software engineering" was coined in the 1960s to address the challenges of developing large-scale software systems, emphasizing the need for systematic approaches and best practices.
  3. Advent of Structured Programming (1970s) - Structured programming introduced principles like modularity and clear control structures (e.g., loops and conditionals), making programs easier to write, understand, and maintain.
  4. Rise of Agile Methodologies (2000s) - Agile methodologies, such as Scrum and Kanban, revolutionized software development by promoting iterative progress, collaboration, and adaptability to changing requirements, leading to faster and more efficient project delivery.

List and briefly explain the phases of the Software Development Life Cycle.
- Requirements: Collecting and documenting user needs and system requirements.
- Design: Developing high-level and detailed software architecture and user interface designs.
- Implementation: Coding and building the software based on design specs.
- Testing: Verifying the software meets quality and functional standards through testing.
- Deployment: Launching the software for users or customers.
- Maintenance: Offering continuous support, updates, and improvements post-deployment.

Compare and contrast the Waterfall and Agile methodologies. Provide examples of scenarios where each would be appropriate.
 - Waterfall is a sequential, linear approach where each phase (e.g., requirements, design, implementation) is completed before moving to the next, and example is building a bridge or a government system with fixed specifications whereas Agile is an iterative and incremental approach, focusing on flexibility, collaboration, and adapting to change and example is developing a mobile app or a startup product where requirements evolve based on user feedback.

Describe the roles and responsibilities of a Software Developer, a Quality Assurance Engineer, and a Project Manager in a software engineering team.
 - Software Developer writes code and implements software solutions based on design specifications and focuses on building functional and efficient software systems.
- Quality Assurance (QA) Engineer ensures software quality by designing and executing test plans and identifies and reports bugs or issues to improve the software's reliability.
- Project Manager oversees the planning, execution, and delivery of software projects and is also responsible in managing timelines, resources, and team coordination to ensure successful project completion.

Discuss the importance of Integrated Development Environments (IDEs) and Version Control Systems (VCS) in the software development process. Give examples of each.
 - Integrated Development Environments (IDEs) are software suites that provide a centralized environment for writing, debugging, and testing code. They integrate essential tools like code editors, debuggers, and compilers into a single platform, making the development process more efficient. Examples are PyCharm, NetBeans and Xcode.
 - Version Control Systems (VCS) are tools that track changes to source code and enable collaboration among team members. They allow developers to work on different features simultaneously, merge changes, and maintain a history of modifications. Examples include GitHub, Mercurial and Bitbucket

What are some common challenges faced by software engineers? Provide strategies to overcome these challenges.
 - Software engineers often face challenges such as changing requirements, tight deadlines, and technical debt. Changing requirements can lead to scope creep and delays, while tight deadlines may force rushed development, compromising quality. Technical debt, resulting from shortcuts or suboptimal solutions, can hinder future progress and increase maintenance costs.

 - To overcome these challenges, engineers can adopt strategies like effective communication to ensure alignment with stakeholders, agile methodologies to adapt to changing requirements, and prioritization of tasks to focus on critical deliverables. Regularly reassessing project goals and timelines also helps manage expectations and maintain progress without sacrificing quality. These approaches enable teams to navigate challenges effectively and deliver successful software projects.

Explain the different types of testing (unit, integration, system, and acceptance) and their importance in software quality assurance.
 - Unit Testing: Tests individual components to ensure they function correctly in isolation.
 - Integration Testing: Verifies interactions between components to ensure they work together as intended.
 - System Testing: Evaluates the entire system’s functionality, performance, and reliability.
 - Acceptance Testing: Confirms the software meets user requirements and is ready for deployment.
 - Importance of Quality Control: Early defect detection through code reviews, automated testing, and continuous integration ensures higher-quality software and a better user experience.

#Part 2: Introduction to AI and Prompt Engineering


Define prompt engineering and discuss its importance in interacting with AI models.
 - Prompt engineering is the process of crafting clear, specific, concise and complete instructions to effectively guide AI models. Prompt engineering help AI models understand user intent, reduce ambiguity, and generate more accurate and useful outputs.

Provide an example of a vague prompt and then improve it by making it clear, specific, and concise. Explain why the improved prompt is more effective.
 - Vague Prompt: "Explain technology."
 - Improved Prompt: "Explain the impact of artificial intelligence on healthcare, focusing on its applications in diagnostics and patient care over the last decade."
Why the Improved Prompt is More Effective:
 - Clarity: The improved prompt narrows down the broad topic of "technology" to a specific area (artificial intelligence in healthcare).
 - Specificity: It directs the AI to focus on particular applications (diagnostics and patient care) and a defined time frame (last decade), ensuring a targeted response.
 - Conciseness: The prompt is brief yet detailed enough to guide the AI effectively, resulting in a more precise and relevant answer.
